# Competitive Programming

> A repository documenting my competitive programming journey through problem solving, algorithm study, contest participation, and continuous improvement.

---

## 📖 About

This repository serves as my personal archive for competitive programming.

The goals of this repository are to:

- 📚 Practice algorithms and data structures
- 💡 Improve problem-solving skills
- 📝 Document the thought process behind each solution
- 🔄 Track progress over time
- 🚀 Prepare for programming contests such as Codeforces, ICPC, and other online judges

Instead of only storing accepted solutions, I also try to document the reasoning, observations, mistakes, and lessons learned from each problem.

## 📁 Problem Directory Structure

Each problem contains:

```text
Problem/
├── solution.cpp
└── README.md
```

The README for each problem generally includes:

- Problem summary
- Key observations
- Thought process
- Algorithm
- Complexity analysis
- Lessons learned
- Alternative approaches (when applicable)

## 📝 Commit Convention

| Prefix      | Description                |
| ----------- | -------------------------- |
| `solve:`    | Solved a new problem       |
| `note:`     | Added algorithm notes      |
| `template:` | Added or updated template  |
| `contest:`  | Contest solutions          |
| `refactor:` | Improved existing solution |
| `fix:`      | Fixed bugs                 |
| `docs:`     | Documentation updates      |

Example:

```text
solve: CF 71A - Way Too Long Words
note: Binary Search - Lower Bound
template: Add DSU implementation
contest: Codeforces Round 1093
docs: Update progress
```

## 🧠 Learning Philosophy

I believe that solving a problem is only the first step.

For every problem, I aim to understand:

- Why the solution works
- Why alternative ideas fail
- Time and space complexity
- General patterns that can be reused
- Common pitfalls to avoid

The objective is long-term understanding rather than simply collecting accepted submissions.
